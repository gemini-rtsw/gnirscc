LdNet loads the code that runs on the icon and sequencer (transputers).
It sends messages to the transputers through the b014 device driver.
Ldnet relies on a network information file (nif) to tell it information of 
what to load, and where to send it.

	example nif file

decode_timeout  20000;
level_timeout 1000;
2, ../tld/NAAC/icon.tld, R0,     0, 10[0],     ,     ;
10, ../tld/NAAC/seq.tld, R2,  2[1],      ,     ,     ;

The first two parameter are used to determine the maximum time ldnet will wait 
when it does a read or write to the transputers.

Next is a line with up to 7 parameters. Each of the transputers will have an
entry like this.  This example has two transputers.  First is the node number 
that the code will go to.  The transputers are set up in a network, and 
each one has a unique node number designated to it.  That is how messages 
can be sent to the correct transputer.  Next is the file name of the code 
to send.  




##############################################
I DON'T KNOW WHAT THE OTHER FIELDS ARE NICK.
 ###############################################
(from parseNode in vxldnet.c)
reset information?
parent node?
?

After the nif file is loaded, the node information about how the network is 
set up is checked to see if it is correct.  If all is OK, ldnet proceeds to 
reset the transputers and send them the  bootstrap information .  
When all of the bootstrap code is sent to the transputers, the actual icon and
sequencer code is downloaded to the transputers.

The code that is sent by ldnet is different from the microcode.  It just sets
up the network, data area, and communications to the outside world.  The 
microcode, which is loaded later, actually sets up the waveforms that 
control the array.
